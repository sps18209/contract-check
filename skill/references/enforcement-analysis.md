# Optional enforcement issue assessment

Run this for a specific provision, asserting party, resisting party, issue, remedy, jurisdiction, forum, posture, and event date. Start with a validated review record. Use `enforcement-template PROJECT REVIEW REQUEST.json`; confirm the suggested issue category and fill unknown fields and sourced facts. The template does not establish legal facts.

Run `enforcement-validate PROJECT REVIEW REQUEST.json`. Supply authority text only from a source the reviewer has inspected. The optional manifest has `schema: 1` and an `authorities` array. Each entry requires `id`, `title`, `jurisdiction`, `court_or_body`, `decision_date`, `precedential_status`, `source_url`, `full_text`, and an exact `excerpt` contained in `full_text`. Set `reviewer_verified: true` only after checking the primary source; otherwise the authority gate abstains. A local excerpt check does **not** authenticate the URL, ensure current validity, or decide whether the passage governs the dispute. Verify those matters separately against primary authority.

Run `enforcement-assess PROJECT REVIEW REQUEST.json ASSESSMENT.json --authorities AUTHORITIES.json` and `enforcement-report ASSESSMENT.json REPORT.md`. Without supplied authority or material facts, the result abstains. The default rule provider produces review questions. For a self-hosted model only, pass `--local-endpoint http://127.0.0.1:8000/v1/chat/completions --model MODEL`; the adapter accepts loopback HTTP only. Inspect all generated hypotheses for invented rules and missing contrary authority. A model cannot approve a revision; use the existing review choices and `apply` controls.

Keep separate: contract formation, interpretation, performance and conditions, defenses, remedies, and collection. The assessment reports no probability. Its `review_pending` status means an issue has supplied inputs for lawyer analysis; it expresses no view about how a court would rule. Do not turn model confidence, citation similarity, or issue labels into an enforcement percentage.

The `contract_check.enforcement.prediction` package is an offline research experiment, unavailable in the CLI and disabled unless called with `enabled=True`. It requires a narrowly defined adjudicated event, label source and quote, pre-outcome features, temporal train/calibration/test partitions, both outcome classes in each, and minimum sample counts. Exclude censored or settled matters rather than coding them as losses. Review selection bias, jurisdiction and issue coverage, leakage, Brier loss, and calibration bins before interpreting its aggregate report. It never feeds an individual contract assessment.
