# Runtime and host integration

Install the repository with `python -m pip install .` when package installation is available, or run `python -m contract_check` from the repository root. The core uses only the Python standard library. Commands:

- `ingest INPUT.txt PROJECT.json` stores the exact UTF-8 source and splits at blank lines into body blocks with stable IDs. It does not infer clauses or headings.
- `apply PROJECT.json PLAN.json REVISED.json` applies approved operations. Plan fields: `base_version`, `source_sha256`, `operations`, optional complete `order`, `order_reason`, `order_approved: true` for reorders, and `decisions`. Every operation has `action`, `id`, `reason`, `approved: true`. `label`, `replace`, and `delete` also require exact `before` text. `insert` requires a new `n`-prefixed ID and `text`, plus a complete order. A heading operation has `kind: heading`, `title`, `level` (1–6), optional `old_label`, and `old_kind` (`Section`/`Article`). Replacing a heading requires an explicit title. Decisions are keyed objects with `status: include|omit|defer` and `reason`. Preserve prior projects and plans as audit records.
- `render PROJECT.json CLEAN.txt --style preserve|decimal|articles [--update-refs] [--map-output MAP.json]` numbers labeled headings only. With `--update-refs`, explicit `Section N` or `Article N` references in body blocks are updated only when every target maps uniquely from `old_label` and `old_kind`. It aborts on unmapped or ambiguous references. Decimal style numbers by heading depth; article style renders top-level Article and lower-level Section. Unsupported cross-reference syntax requires review.
- `check PROJECT.json CLEAN.txt` reports duplicate numbered headings, unresolved explicit singular references, and duplicate quoted `"Term" means` definitions, with a limited scope. Exit 2 means findings; exit 0 does not mean substantive completeness.
- `validate-review PROJECT.json REVIEW.json` checks version, finding shape, and verbatim block quotes. It does not validate analysis or law.
- `compare ORIGINAL.json REVISED.json DIFF.json [--style ...]` returns insertion, deletion, replacement, or movement by ID and a unified text diff. The diff is not Word tracked changes.
- `audit ORIGINAL.json REVISED.json FLAGS.json` flags changed numerical strings and words such as `not`, `unless`, `shall`, and `may`, plus block insertions/deletions. Review each flag and all substantive edits; token matches do not establish semantic equivalence.

Host capability adapter: use file readers or OCR for intake, code execution for core operations, research for law, and document export when available. Verify text extraction and attachments before substantive review. If execution is unavailable, preserve the same state and decision fields in the conversation and identify which checks were manual. Do not claim cross-session persistence without a durable store. External APIs are optional and require configured endpoints, authorization, bounded retries, minimal data transfer, and visible failure. This repository does not contain vendor-specific connectors.
