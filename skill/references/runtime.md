# Runtime and host integration

In a distributed skill folder, run `python scripts/contract_check_cli.py`. In the source repository, run `python -m contract_check` from the repository root, or install with `python -m pip install .` when package installation is available. The core uses only the Python standard library. Commands:

- `ingest INPUT.txt PROJECT.json` stores the exact UTF-8 source and splits at blank lines into body blocks with stable IDs. It does not infer clauses or headings.
- `apply PROJECT.json PLAN.json REVISED.json [--review REVIEW.json --choices CHOICES.json]` applies approved operations. Plan fields: `base_version`, `source_sha256`, `operations`, optional complete `order`, `order_reason`, `order_approved: true` for reorders, and `decisions`. Every operation has `action`, `id`, `reason`, `approved: true`. `label`, `replace`, and `delete` also require exact `before` text. `insert` requires a new `n`-prefixed ID and `text`, plus a complete order. A heading operation has `kind: heading`, `title`, `level` (1–6), optional `old_label`, and `old_kind` (`Section`/`Article`). Replacing a heading requires an explicit title. For a substantive edit, set `classification: substantive` and `finding_id`; provide the review and choice record. Only `adopt` and `custom` permit a linked edit. Decisions about optional sections are keyed objects with `status: include|omit|defer` and `reason`. Preserve prior projects, choices and plans as audit records.
- `render PROJECT.json CLEAN.txt --style preserve|decimal|articles [--update-refs] [--map-output MAP.json]` numbers labeled headings only. With `--update-refs`, explicit `Section N` or `Article N` references in body blocks are updated only when every target maps uniquely from `old_label` and `old_kind`. It aborts on unmapped or ambiguous references. Decimal style numbers by heading depth; article style renders top-level Article and lower-level Section. Unsupported cross-reference syntax requires review.
- `check PROJECT.json CLEAN.txt` reports duplicate numbered headings, unresolved explicit singular references, unsupported compound/subclause reference forms, and duplicate quoted `"Term" means` definitions, with a limited scope. Exit 2 means findings; exit 0 does not mean substantive completeness.
- `validate-review PROJECT.json REVIEW.json` checks version, finding shape, and verbatim block quotes. It does not validate analysis or law.
- `compare ORIGINAL.json REVISED.json DIFF.json [--style ...]` returns insertion, deletion, replacement, or movement by ID and a unified text diff. The diff is not Word tracked changes.
- `audit ORIGINAL.json REVISED.json FLAGS.json` flags changed numerical strings and words such as `not`, `unless`, `shall`, and `may`, plus block insertions/deletions. Review each flag and all substantive edits; token matches do not establish semantic equivalence.
- `extract-docx INPUT.docx TEXT.txt MANIFEST.json` extracts paragraphs and table cells in order. Inspect the manifest warnings for tracked changes, headers, footnotes, comments, drawings, and field codes. The original file remains authoritative; format and layout are not retained.
- `cards PROJECT.json REVIEW.json CHOICES.md` renders a decision sheet. It does not record selections automatically; capture them in the approved plan.
- `choice-template PROJECT.json REVIEW.json CHOICES.json` creates an unselected JSON record. After the user chooses, fill every selection with `choice: adopt|retain|defer|custom` and a reason; custom choices require `custom_instruction`. Run `validate-choices PROJECT.json REVIEW.json CHOICES.json`. A Markdown card is a presentation, while this JSON is the controlled record.
- `inventory PROJECT.json INVENTORY.json` suggests heading labels and inventories quoted `"Term" means` definitions. Confirm all candidates; the text's typography alone cannot establish contract structure.
- `preview PROJECT.json STRUCTURE.md` shows three layout choices and a candidate-section decision table. These are prompts, not mandatory contract content.
- `report ORIGINAL.json REVISED.json REPORT.md [--style ...]` combines recorded decisions, lexical flags, and a text diff. It does not replace semantic review.

Host capability adapter: use file readers or OCR for intake, code execution for core operations, research for law, and document export when available. Verify text extraction and attachments before substantive review. If execution is unavailable, preserve the same state and decision fields in the conversation and identify which checks were manual. Do not claim cross-session persistence without a durable store. External APIs are optional and require configured endpoints, authorization, bounded retries, minimal data transfer, and visible failure. This repository does not contain vendor-specific connectors.
